    Changelog¶

    Unreleased¶

    • No additional changes queued.

    0.1.9 [2026-10-17]¶

    • Omit xdist worker-header-only comments when a report has no diagnostic representation, preventing otherwise passing grouped exports from exhausting comment limits. Preserve actual/custom diagnostics, privacy opt-ins and limits.
    • Preserve opt-in reports when integer parameters exceed Python's decimal conversion limit at capture time: use the existing unsupported-value placeholder instead of losing the case report or aborting parameter comments. Keep valid integers, privacy defaults and interpreter settings unchanged.
    • Create missing parent folders for requested local case reports at write time, matching preview/archive exports. Preserve genuine filesystem errors, atomic replacement and prior files; newly created folders can remain after failure.
    • Avoid repeated linear Test-key scans during plugin result aggregation. Preserve first-observed ordering, grouping contents/statuses, public model APIs and final payload hooks, at the cost of one index entry per unique Test key.
    • Reject empty or whitespace-only upload base URLs as configuration usage errors (exit 4) before tests run, instead of failing later while preparing an upload (exit 3). Preserve nonblank values and credential-free offline/collect-only modes.

    0.1.8 [2026-10-17]¶

    • Report expected path expansion/resolution failures as option-specific pytest usage errors (exit 4). Preserve non-strict resolution, expansion conventions, collision checks and write-time failures, including Python's symlink-loop behavior difference between 3.12 and 3.13+.
    • Report missing authentication environment variables and nonexistent CA bundle paths as concise pytest usage errors (exit 4), avoiding configuration internal tracebacks/exit 3. Offline/collect-only and runtime HTTP handling are unchanged.
    • Preserve report-writing errors when temporary-file cleanup also fails, keeping the existing Xray error or offline warning/exit handling and identifying the leftover temporary path. Skip cleanup after successful atomic replacement.

    0.1.7 [2026-10-17]¶

    • Classify disallowed duplicate Test keys as collection failures, avoiding internal errors and xdist worker/controller errors while preserving diagnostic order and opt-in grouping. Nonzero collection-error exits replace internal-error exit 3.
    • Report malformed Test-key markers as collection errors before fixtures or uploads, including xdist and continue-on-collection-errors, instead of internal errors. Preserve valid marker forms and duplicate-key policy.
    • Use set membership for duplicate Test-key collection validation, avoiding quadratic list scans for large suites while retaining diagnostic order, repeated-key handling and opt-in grouping. No new flags or default changes.

    0.1.6 [2026-10-16]¶

    • Recheck a draft's tag before publication and verify the returned published release identity/state and tag target; never report success for a retargeted draft.
    • Add relevant shared README badges and first-party measured coverage/metadata snapshots, with explicit scope, provenance and freshness. No external account.
    • Measure all plugin source files including Python subprocesses in the existing read-only Python 3.12 CI job; retain the full 3.13/3.14 matrix.
    • Enable automatic version tags and GitHub Releases after verified PyPI publication, with exact artifacts, version notes, safe retries and conflict protection.
    • Add beginner release/backfill instructions after explicit permission confirmation and independent review; verify the 0.1.5 tag, artifacts and idempotent retry.
    • Publish shared README badges in PyPI metadata. No plugin runtime changes.

    0.1.5 [2026-10-16]¶

    • Validate malformed defects markers during collection when Xray reporting is on, before fixtures or uploads, including xdist and continue-on-collection-errors.
    • Report a fixed collection error without displaying marker values or invoking arbitrary repr. Valid lists, including empty lists, retain their string values; no Jira-key format regex is imposed. Reporting-disabled runs remain unaffected.
    • Document beginner configuration fixes and retain the prohibition on bypassing browser certificate/security warnings.

    0.1.4 [2026-10-16]¶

    • Isolate evidence and defect list ownership per mapped Jira Test key. A later case for one key no longer changes another key's attachments or defects.
    • Prevent attachment inflation when parameter cases map to the same multiple keys; retain legitimate identical attachment occurrences, status precedence and comments.
    • Add serial/xdist offline regressions for mixed/shared mappings in both orders.
    • Document repository-specific standing maintenance authorization without weakening independent review, evidence, CI or trusted-publishing safeguards.

    0.1.3 (2026-10-15)¶

    • Confirm Generic as the target Test type on Jira Server/Data Center with Xray 8.5.3-j10.
    • Correct README, website and compatibility guidance; retain native-iteration limitations.
    • Documentation-only release: runtime, credentials and publishing permissions unchanged.

    0.1.2 (2026-10-15)¶

    • Correct Jira/Xray integration positioning: Jira with Xray is the required product foundation.
    • Lead the complete guide with prerequisites, Test/Execution mapping, authentication and import.
    • Retain offline preview, local case audit and archives as integration support facilities.
    • No runtime changes, network enforcement, credentials or publishing permission changes.

    0.1.1 (2026-10-15)¶

    • Replace the option-heavy introduction with a progressive, runnable tutorial covering local reports, values/identity choices, failures, offline Xray export, full comment archival and optional upload. Keep reference material below it.
    • Execute tutorial commands and check actual report excerpts against installed wheels in CI. Replace obsolete README.rst guidance with a maintained-guide link.
    • No runtime feature changes or expanded compatibility claims.

    0.1.0 (2026-10-15)¶

    • Release the validated 0.1.0a2 feature set as stable: local case/attempt reporting and optional aggregate Xray comments, including bounded comments with full local archival, transport failure handling and partial-upload suppression.
    • Michael reported successful validation and explicitly authorized stable publication. This is user-reported evidence, not independent observation of exhaustive server behavior or confirmation of Automatic's effective Test type.
    • No runtime feature changes from 0.1.0a2. Native iteration rows and datasets remain unsupported; documented platform/plugin and status-mapping limits apply.

    0.1.0a2 (2026-10-15)¶

    • Bound HTTP connect/read waits; validate authentication and import responses.
    • Surface publishing failure with a nonzero exit; withhold incomplete remote imports.
    • Preserve failed retry phases in legacy aggregation and write local exports atomically.
    • Add failure, retry and worker regression coverage, installed-wheel CI checks, and complete beginner usage documentation for the PyPI long description.

    • Keep native iterations unimplemented and stable publication blocked on target validation.

    • Add configurable UTF-8 comment bounds with required full local archival before truncation, and prevent partial uploads after fail-fast or collection failures.

    • Prepare exact 0.1.0a2 artifacts in the existing manual publishing workflow; publication uses the existing manual approval workflow.
